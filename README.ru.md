# flutter_team_logger

Flutter-виджеты для отображения логов из [team_logger](https://pub.dev/packages/team_logger) в UI.

> **Статус: ранняя стадия.** Пока делается для внутреннего использования;
> публичный API может меняться между minor-версиями без предупреждения.

## Возможности

- `Logs` — готовый экран логов: живое обновление из `LogStorage`, пауза
  при скролле вверх со счётчиком "новых логов", возобновление с анимацией
  подгрузки и фильтр по level / logger / traceId / tag.
- `LogItem` — виджет одного лога, можно использовать отдельно от `Logs`.
- `LogDetails` — экран со всем содержимым одного лога, открывается по тапу
  на лог в `Logs`, с раскрывающимся деревом его `data`.

Пакет только отображает то, что уже собрал `team_logger` — настройка
логирования (логгеры, publisher'ы, темы) целиком остаётся задачей
`team_logger`.

## Начало работы

```yaml
dependencies:
  team_logger: ^0.7.0
  flutter_team_logger: ^0.7.0
```

## Использование

```dart
final logStorage = LogStorage(maxCount: 1000);
final log = Logger('app')..publisher = MultiPublisher([logStorage]);

// ...

log.i('hello');

// ...

Logs(
  theme: LogMainTheme.defaultActiveTheme,
  logStorage: logStorage,
)
```

Полноценный пример — в `example/`.

## Экран деталей

По тапу на лог открывается `LogDetails`: шапка, сообщение, ошибка и
стек-трейс целиком, а также дерево данных лога, раскрывающееся узел за
узлом — и объекты, и мапы, и коллекции.

У экрана два режима.

**As logged** показывает ровно то, что печатает консоль: подстановки `view`
применены, свойства `hidden` не показаны.

**Real data** показывает то, что за ними стоит: значение под каждым `view` и
свойства, помеченные `hidden`. Свойства, добавленные через `computed`, видны
в обоих режимах и помечены бейджем — реального значения за ними нет.

> **Режим real data не применяет `Loggable.sanitizer`.** Он затем и нужен,
> чтобы показать скрытое логом, и читает объекты прямо из памяти, как
> инспектор в отладчике, — правило редактирования ему не преграда. Что не
> должно попасть на экран, не должно попадать и в лог: `view` и sanitizer —
> способ сохранить лог читаемым и вывод чистым, а не способ уберечь секрет от
> того, у кого приложение в руках.

Объекты, отображаемые через `Loggable.registerTypeConverter`, остаются
листьями: реестр конвертеров приватен в `team_logger`, поэтому текст у них
верный, но раскрыть их по свойствам нельзя. Ленивые `Iterable` — тоже
листья: перечислить такой для дерева значило бы его материализовать.
