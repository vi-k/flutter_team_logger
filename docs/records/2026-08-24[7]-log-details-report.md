## Что сделано

Закрыт пункт бэклога «Полноценный вывод информации по конкретному логу:
раскрытие всех вложенных данных».

По тапу на лог в `Logs` открывается `LogDetails` — экран, показывающий лог
целиком: шапку, сообщение, дерево `data` с раскрытием узлов, ошибку и
стек-трейс, всё без ограничений по высоте. Тумблер в AppBar переключает два
режима: «as logged» (то же, что печатает консоль) и «real data» (значения
под `view`, показанные `hidden`, без `Loggable.sanitizer`).

Коммиты, по одному на задачу плана:

1. `refactor: extract BorderContainer into uikit`
2. `feat: add the log data tree node model`
3. `feat: render node names and values in the tree model`
4. `feat: add the tree row widget`
5. `feat: add the log details screen`
6. `feat: open the details screen on log tap`
7. `example: show hidden, computed and view data`
8. `docs: document the log details screen, bump to 0.7.1`

## Где реализация разошлась с планом

- **`LogNodeKind.index` → `element`.** `Enum` в Dart уже объявляет
  `int index`, и константа с таким именем не компилируется. Поймано первым
  же прогоном тестов.
- **Раскрытие первого уровня убрано из `initState`.** План раскрывал детей
  корня, но корень как строка не рисуется вовсе — его дети и есть первый
  уровень, видимый всегда. Код из плана раскрывал таким образом второй
  уровень, что расходилось со спекой. Теперь `_expanded` стартует пустым.
  Поймано smoke-тестом: в дереве сразу был виден `city: "Berlin"`.
- **`_Label`** — приватная обёртка над `BorderContainer` в шапке экрана:
  пять вызовов подряд с одинаковыми четырьмя флагами скругления читались
  хуже.
- **`prefer_foreach`** — два цикла в `_flatten` заменены на `forEach(walk)`
  по требованию линта.
- **В `example` добавлен вложенный `Address`** — без него у `Payment` не
  было раскрываемого узла, и дерево нечем было показать.

## Как проверено

- `dart analyze` в корне и в `example/` — `No issues found!`.
- `flutter test` — 13 тестов модели дерева (`test/log_node_test.dart`):
  разбор `Loggable`/`LoggableData`/`LoggableMultiData`/`Map`/`List`/`Set`/
  `LoggableWrapper`, зонд `computed`, оба режима, рендер значения с `view` и
  без, пути от позиций.
- Временный widget-smoke-тест (в репозиторий не попал, лежит в scratchpad
  сессии): экран рисуется; в режиме «as logged» виден `**** 1234`, а
  `accuracy` отсутствует; в «real data» появляется настоящий номер карты,
  `accuracy` с бейджем `hidden` и `<computed>` с бейджем `computed`; тап по
  вложенному объекту превращает сводку в отдельные строки; лог без данных
  открывается без дерева и без исключений.
- `cd example && flutter build macos --debug` — успешно.

Визуальная проверка вживую (цвета, отступы, поведение на узком экране) не
делалась — это за владельцем.

## Замечено по пути

- `LoggableData.name` в `team_logger` 0.7.0 всегда возвращает строку
  `'type'`: геттер читает `_type.name` (это `Prop.name` конструктора
  `TypeProp`, то есть литерал `'type'`), а сеттер пишет в `typeName`.
  Похоже на дефект. Имя класса приходится брать как
  `data.type.typeName ?? data.type.value.toString()` — так его берёт и сам
  `team_logger` внутри `toLogString`.
- В рабочем дереве обнаружена не принадлежащая этой работе правка
  `analysis_options.yaml` (добавлены `android/ios/windows/macos/linux` в
  `analyzer.exclude`). По `AGENTS.md` чужие правки не коммитятся вместе со
  своими — файл не тронут и не закоммичен.
