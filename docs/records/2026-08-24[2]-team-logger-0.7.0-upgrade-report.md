## Задача

Обновить зависимость `team_logger` в `flutter_team_logger` до последней
версии на pub.dev (0.7.0, опубликована 2026-08-23), минуя промежуточные
версии team_logger (0.5.2, 0.6.0), под которые отдельного релиза
`flutter_team_logger` не выпускалось.

## Метод

Поднял ограничения версий, выполнил `flutter pub upgrade`, прогнал
`dart analyze` в корне и `example/`, каждую ошибку разобрал по исходникам
`team_logger` 0.7.0 и `ansi_escape_codes` 4.0.1 из локального pub-кеша
(`~/.pub-cache/hosted/pub.dev/...`), а не по одним записям changelog — чтобы
понять точную семантику новых обязательных параметров, а не гадать.

## Найденные breaking changes и правки

1. `ansi_escape_codes` 4.0.0: `Parser.matches` заменён на `Parser.pieces`
   (тот же `Iterable`, поля `entity`/`state` не изменились). Правка:
   `lib/src/ansi_utils.dart`.
2. `ansi_escape_codes` 4.0.0: топ-level константы стилей (`gray8` и
   соседние) перенесены в класс `Styles`. Правка: `example/lib/logging.dart`
   — `ansi.gray8` → `ansi.Styles.gray8`.
3. `team_logger` 0.7.0: `LogTheme.formatValue`/`formatMessage` получили
   обязательный именованный параметр `escapeAnsiCodes` (защита от подмены
   стиля через ANSI-последовательности в самом тексте лога). Разобрал по
   исходнику `printer/log_message.dart`, как это делает собственный принтер
   team_logger: внутренний вызов `formatValue` экранирует сырой текст,
   внешний `formatMessage` — нет (иначе задвоил бы экранирование уже
   применённых кодов темы). Хотел взять готовое значение из
   `LoggableConfig.appEscapeAnsiCodes`, но оно помечено `@internal` (только
   для internal-package use) — analyzer предупредил
   `invalid_use_of_internal_member`. Вместо этого — публичная константа
   `LoggableConfig.defaultEscapeAnsiCodes` (`true`), тот же результат в
   подавляющем большинстве случаев, без обращения к internal API. Правка:
   `lib/src/log_item.dart` (сообщение и текст ошибки).

## Не потребовало правок

- Собственных `Publisher`/`Logger` пакет не реализует — блок изменений в
  `logger_builder` 0.8.0 (переименования, sealed-иерархия и т.п.) не
  задевает; в коде нет обращений ни к одному из перечисленных в changelog
  символов (проверено `grep`).
- `LoggableConfig` (`enumDotShorthand`, `collectionMaxCount`,
  `doubleFormat`/`intFormat` и т.д.) используется только в `example/`, поля
  не переименованы — проверено по исходнику `loggable_config.dart`.
- `Log.tags`/`Log.traceIds` теперь неизменяемые снэпшоты — код их только
  читает, мутаций не было.
- Поведенческие (не API) изменения — форматирование чисел без пакета
  `format`, экранирование control-последовательностей в данных,
  grapheme-based замер ширины в `ConsoleLogPrinter` — правок в этом пакете
  не требуют: он их либо не использует (`ConsoleLogPrinter` закомментирован
  в примере), либо получает уже готовый форматированный текст от
  `team_logger`.

## Версия и проверка

- `pubspec.yaml` (корень и `example/`): `team_logger` `^0.5.1` → `^0.7.0`,
  `ansi_escape_codes` `^3.1.2` → `^4.0.1`.
- Версия пакета: 0.5.0 → 0.7.0 (конвенция: minor пакета = minor
  `team_logger`, см. `docs/conventions.md`).
- `CHANGELOG.md` дополнен записью 0.7.0.
- `dart analyze` (корень и `example/`, без указания пути) — чисто.
- `flutter pub upgrade` попутно отредактировал `analysis_options.yaml` в
  обоих местах: конвертировал `exclude` из старого map-синтаксиса
  (`"web/**": true`) в новый list-синтаксис и добавил исключения под
  android/ios/windows/macos/linux. Сначала откатил как не относящееся к
  задаче, но `dart analyze` без указания пути (а не `dart analyze lib`,
  которым проверял правки по ходу) показал `invalid_section_format` на
  старом синтаксисе — это не косметика, старый формат `exclude` больше не
  принимается текущим analyzer. Применил минимальный вариант вручную:
  тот же набор исключений (`web/**`, `build/**`, `assets/**`) в
  list-синтаксисе, без добавления платформенных путей — это не относится к
  обновлению team_logger.
